Pure functional language:
- Consists of function declarations. Each function declaration is a square of tiles. Each tile is either a function call, a constant, or a pipe. Each function declaration marks 1 side as an output, and 0-3 sides as inputs.
- Each function is represented both with it's declaration and it's calls. When a function is declared, it is a square of tiles. When a function is called, it is a singular tile. All functions are in global scope. This implies recursion and cross-recursion.
- Constants are just functions with 0 inputs. "Pipes" are fundamentally just the identity function, but with the added benefit of being able to be crossed in the graphical view. Pipes are directional.
- Pipes can be split off, but not united. Specifically, this means that 1 output can serve to many different inputs, but each input needs to come from 1 output.
- For each function call, each input side can be specified to be either lazy or eager, and sides of the declaration view can be 1-to-1 arbitrarily mapped to sides of the call view.
- The point of entry is just another function declaration with a special name. (in case of an esolang, inputs of the main function correspond to command line args. in case of a zachlike, inputs correspond to test cases of a level specification.)
- There are 2 data types: the integer, and the immutable list (can contain other lists).
- A list "constructor" is just the empty list constant.
- Every operation looks like a function call.
- Fundamental operations: choice, comparison, addition, subtraction.

- choice function is best used with lazy evaluation for arguments B,C.
choice table:
A↓?B,C      |
int         |{nonzero, zero} maps to {B,C}
list        |length of list used for evaluation like for integers

comparison table:
A↓>=B→  |int                                    |list
int     |1 if A>=B, else 0                      |always 0, ints are always "smaller" than lists
list    |always 1, lists are "bigger" than ints |1 if A is the same as B (item by item), 0 otherwise

addition table:
A↓+B→   |int                                    |list
int     |sum                                    |list B with A, prepended
list    |list A with B, appended                |concatenation

subtraction table:
A↓-B→   |int                                    |list
int     |difference A-B                         |the value of item in list B on idx A (accessor)
list    |copy of A with value at idx B, popped  |???

(when idx for popping and accessing is out of bounds, it is clamped in bounds. For empty list, popping and accessing return another empty list.)

- Possible candidates for operation "list - list", inspired by the set difference:
- 1. For each element, count the number N of element X in B. In A, remove first N instances of X.
- 2. Remove from A all instances of items encountered in B.

- implementation of N^N:
------------
N_TO_POWER_N N:
return EXPONENTIATE(N, N)
------------
EXPONENTIATE BASE, POWER:
return choice(
    POWER,
    <lazy> MULTIPLY(
        BASE,
        EXPONENTIATE(
            BASE,
            POWER - 1
        )
    ),
    1
)
------------
MULTIPLY A, B:
return choice(
    B,
    <lazy> MULTIPLY(
        A,
        B-1
    ) + A,
    0
)

SORT LEFTOVER_LIST:

ELEMENT_AT_FOUND_IDX <- IDX_OF_MAX_ELEMENT - LEFTOVER_LIST  // list accessor

// in normal languages these would cause errors from out of bounds in LEFTOVER_LIST at the end of recursion,
// but here we simply get back garbage data and ignore it using choice()

return choice(
    LEFTOVER_LIST,
    <lazy> SORT(
        LEFTOVER_LIST_WITHOUT_FOUND_IDX
    ) + ELEMENT_AT_FOUND_IDX,   // appending to list from recursive call
    EMPTY_LIST()
)

FIND_IDX_OF_MAX_POSITIVE_ELEMENT LIST, ITER_IDX, FOUND_IDX, FOUND_ITEM:

ITER_ITEM <- ITER_IDX - LIST  // list accessor
NEW_FOUND_IDX <- choice(
    (ITER_ITEM >= FOUND_ITEM),
    ITER_IDX,
    FOUND_IDX
)
NEW_FOUND_ITEM <- choice(
    (ITER_ITEM >= FOUND_ITEM),
    ITER_ITEM,
    FOUND_ITEM
)

return choice(
    LIST,
    <lazy> FIND_IDX_OF_MAX_POSITIVE_ELEMENT(
        LIST - 1,
        ITER_IDX + 1,
        NEW_FOUND_IDX,
        NEW_FOUND_ITEM
    ),
    NEW_FOUND_IDX
)
